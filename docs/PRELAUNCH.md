# مراجعة ما قبل الإطلاق

> هذه القائمة تفصل ما تم تقنياً عمّا يحتاج قرار المشغّل أو حساباً أو اختباراً تشغيلياً. **النظام ليس «جاهزاً للإنتاج» بعد** — راجع البنود ☐.

## الأمان والخصوصية
| البند | الحالة |
|---|---|
| RLS على كل الجداول المعروضة؛ RPCs بتفويض داخلي؛ صلاحيات الجداول مطابقة بين المحلي والسحابة (اختبار db:50) | ✔ |
| لا مفاتيح سرية في الواجهة أو المستودع؛ العميل بالمفتاح العام فقط | ✔ |
| ملفات طبية في bucket خاص، حجر وفحص محتوى، روابط قصيرة العمر | ✔ (فحص فيروسات بمزود حقيقي ☐) |
| MFA (TOTP) مفروض للإدارة | ✔ (توسيعه للأطباء والصيادلة قرار ☐) |
| حماية كلمات المرور المسربة (HIBP) | ☐ تتطلب خطة Supabase Pro |
| تدوير المفتاح السري و Access Token اللذين ظهرا في المحادثة | ☐ على المالك |
| سجل تدقيق للبحث/الدمج/الحالات/الدعوات/الملفات بلا محتوى طبي | ✔ |
| وصول استثنائي مؤقت ومسبب للسوبر أدمن | ☐ غير مفعّل عمداً (لا وصول) |
| اختبار اختراق مستقل | ☐ |

## البيانات والتشغيل
| البند | الحالة |
|---|---|
| migrations متسلسلة ومسجلة على السحابة (0001–0019) | ✔ |
| seed اصطناعي محلي فقط | ✔ |
| مهام مجدولة: انتهاء المهلة، الإشعارات، التذكيرات، فحص الملفات | ✔ تعمل (لوحة صحة النظام) |
| النسخ الاحتياطي و PITR، وتحديد RPO/RTO، وتجربة استعادة فعلية | ☐ قرار خطة + اختبار |
| سياسة الاحتفاظ والتصدير وإغلاق الجهة ومعالجة المواعيد المستقبلية عند التعليق | ☐ قرار المشغّل |
| مكان الاستضافة والامتثال المحلي والموافقات واعتماد الوصفات قانونياً | ☐ قرار قانوني |
| مراقبة الأعطال والتنبيه (مثلاً على صفوف `dead` وفشل cron) | ◐ اللوحة موجودة؛ تنبيه خارجي ☐ |

## التكاملات
| البند | الحالة |
|---|---|
| SMS / OTP | ☐ يحتاج مزوداً مدفوعاً |
| Push (FCM/Expo) | ☐ التجريد جاهز؛ in-app يعمل |
| البريد (دعوات/تأكيد) عبر SMTP خاص | ☐ (مزود Supabase الافتراضي محدود) |
| استضافة الواجهة (Vercel) + ضبط Site URL في Supabase | ☐ `vercel.json` جاهز |
| طباعة صامتة (خدمة طباعة محلية) | ☐ خارج النطاق الحالي؛ الطباعة عبر المتصفح |
| ربط أجهزة المختبر الآلي | ☐ تكامل لاحق |
